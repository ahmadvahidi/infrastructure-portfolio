When a driver update disables the service it needs

A vendor update utility stopped launching after installing its own updates. The cause was a service left in a disabled state.

Problem

A user could no longer start the manufacturer's update tool after applying updates through it. The error message pointed nowhere useful.

Approach

The tool depends on a background management service. I checked the service state rather than reinstalling the application.

Solution

The service had been set to disabled during the update. Re enabling and starting it restored the tool. Because the user was not technical and time was limited, I prepared three options in advance, a guided phone call, a remote session, or an on site visit, and let the user choose rather than assuming.

Result

Resolved without a reinstall, and without making a non technical user feel like they were being handed a homework assignment.

What I learned

  • When an application will not start, check its dependent services before you reinstall.
  • Offer support options without ranking them. Letting the user choose the channel gets a faster answer than proposing the one you prefer.
