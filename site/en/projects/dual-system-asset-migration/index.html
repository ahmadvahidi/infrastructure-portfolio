Migrating a company inventory into two systems in parallel

606 assets and 129 licenses moved from a spreadsheet into two asset management systems, then consolidated into one after an evaluation period.

Problem

The complete IT inventory, worth roughly two million euros, lived in a spreadsheet. No history, no assignment to users, no depreciation, no license overview, and no way to answer who has which device.

Approach

Rather than betting on one product, I migrated into two candidate systems in parallel and ran both for an evaluation period. Same source data, same categories, so the comparison was fair.

Solution

System A received the data split into assets, accessories, components and licenses across 15 categories with a custom field set for company specific attributes. System B received nine object types including a custom asset type for furniture, with financial data attached to each object. After the evaluation, one system was chosen and the other kept read only as a reference.

Result

A complete, queryable inventory with documented value, plus a decision made on evidence rather than on a vendor demo.

What I learned

  • Evaluating two systems with real data costs more time than reading comparison articles and is the only method that produces a defensible decision.
  • Field names in an API rarely match the labels in the interface. Check the API reference before mapping columns.
  • A typo in a system generated internal name can be permanent. Check the name field before saving anything that becomes an identifier.
