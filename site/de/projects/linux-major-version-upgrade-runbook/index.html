Einen produktiven Linux-Server um zwei Versionen auf einmal upgraden

Ubuntu 22.04 auf 24.04 und Java 17 auf 25 auf einem Server, der ein Integrationstool hostet, ausgeführt nach einem geschriebenen Runbook statt improvisiert.

Problem

Ein Synchronisationstool, das zwei Issue-Tracking-Systeme synchron hält, brauchte eine neuere Version. Diese Version brauchte eine neuere Java-Laufzeit, die wiederum eine neuere Distributionsversion brauchte. Drei Upgrades übereinander gestapelt, auf einem Server, von dem andere Teams während der Arbeitszeit abhingen.

Vorgehen

Ich schrieb vor dem Start ein Runbook: Bestandsaufnahme des aktuellen Zustands, Snapshot und Rollback-Punkt, Abhängigkeitsprüfung für jedes installierte Paket, dann das Upgrade in Phasen mit einem Verifikationsschritt nach jeder Phase. Ich habe die Schritte bewusst nicht verkettet, damit ein Fehler an jedem Punkt ein System hinterlässt, das noch bootet und noch die alte Version bedient.

Lösung

Zuerst das Distributions-Upgrade, dann die Java-Laufzeit, dann die Anwendung. Nebenbei behob ich eine systemd-Unit, die monatelang einen falschen Monitoring-Alarm erzeugt hatte, weil der Dienst sich als bereit meldete, bevor er es tatsächlich war.

Ergebnis

Der Upgrade-Pfad wurde Phase für Phase ohne ungeplante Ausfallzeit ausgeführt, und ein langjähriger Fehlalarm verschwand als Nebeneffekt.

Was ich gelernt habe

  • Wenn drei Upgrades voneinander abhängen, schreibe die Reihenfolge auf. Die Abhängigkeitskette ist unter Zeitdruck nicht offensichtlich.
  • Ein Monitoring-Alarm, den alle gelernt haben zu ignorieren, ist ein Bug, kein Hintergrundrauschen.
