Eine volle Platte mit Automatisierung statt einer größeren Platte lösen

Ein Server lief aus dem Speicher. Die Lösung kombinierte eine automatisierte Offsite-Kopie, eine Änderung der Datenaufbewahrungsrichtlinie und eine Plattenexpansion, in dieser Reihenfolge.

Problem

Ein loglastiger Server füllte seine Platte und hörte auf, Daten anzunehmen. Einfach Speicher hinzuzufügen hätte denselben Ausfall um ein paar Wochen verzögert.

Vorgehen

Ich behandelte die volle Platte als drei getrennte Probleme: die Daten, die bereits existierten und erhalten werden mussten, die Richtlinie, die Daten unbegrenzt ansammeln ließ, und die Kapazität, die wirklich zu klein war.

Lösung

Ein automatisierter Workflow kopiert Daten nach Zeitplan auf einen dedizierten Backup-Server über SSH, die Index-Lifecycle-Richtlinie wurde angepasst, damit alte Daten automatisch ausgemustert werden, und erst dann wurde die Platte auf eine sinnvolle Größe erweitert.

Ergebnis

Der Server erholte sich, historische Daten wurden erhalten, und das Wachstum ist jetzt durch Richtlinie begrenzt statt durch die Größe der Platte.

Was ich gelernt habe

  • Eine volle Platte ist meist ein Aufbewahrungsrichtlinien-Problem im Kapazitätskostüm.
  • Einige SSH-Implementierungen verlangen einen Schlüssel im klassischen PEM-Format. Wenn die Schlüssel-Authentifizierung ohne sichtbaren Grund fehlschlägt, prüfe das Schlüsselformat, bevor du Berechtigungen debuggst.
