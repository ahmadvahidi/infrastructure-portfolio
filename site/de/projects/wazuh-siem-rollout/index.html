Einführung eines selbst gehosteten SIEM in sechs Phasen

Wazuh als zentrales SIEM auf Docker eingeführt, in sechs Phasen geplant, damit die Einführung nicht auf halbem Weg stecken bleibt.

Problem

Das Firmennetz hatte Endpoint-Schutz und Firewall-Logging, aber keinen zentralen Ort, an dem Sicherheitsereignisse von Windows-Servern, Linux-Hosts und Netzwerkgeräten korreliert werden konnten. Niemand konnte die Frage beantworten, was letzten Dienstag auf dieser Maschine passiert ist, ohne sich selbst auf der Maschine anzumelden.

Vorgehen

Statt einer Big-Bang-Installation schrieb ich einen Sechs-Phasen-Plan und ließ ihn genehmigen, bevor ich irgendetwas anfasste: Phase 0 Dimensionierung und Host-Vorbereitung, Phase 1 Einzelknoten-Deployment auf Docker über Portainer, Phase 2 Agent-Rollout auf Servern, spätere Phasen für die Integration von Backup-Software, Active Directory und Firewall. Jede Phase hatte eigene Erfolgskriterien, damit das Projekt zwischen den Phasen pausiert werden konnte, ohne ein halb konfiguriertes System zu hinterlassen.

Lösung

Wazuh-Manager, Indexer und Dashboard laufen als containerisierter Stack, verwaltet über Portainer auf einem dedizierten Linux-Host. Agents wurden zuerst auf dem Serverbestand ausgerollt, später auf den Arbeitsplätzen. Ich baute außerdem ein interaktives zweisprachiges Dashboard, damit Kollegen, die kein englisches Sicherheitsvokabular lesen, das Alarmbild trotzdem verstehen konnten.

Ergebnis

Phasen 0 bis 2 sind abgeschlossen und das SIEM ist täglich für die Alarm-Sichtung im Einsatz. Die phasenweise Struktur erwies sich als der wertvollste Teil: Sie machte das Projekt in jedem Schritt für das Management überprüfbar.

Was ich gelernt habe

  • Ein Rollout-Plan mit expliziten Stopp-Punkten übersteht Unterbrechungen. Ein einzelnes langes Installationsskript nicht.
  • Ein SIEM, das niemand liest, ist nur Plattenverbrauch. Plane die Sichtungs-Routine gleichzeitig mit dem Deployment.
