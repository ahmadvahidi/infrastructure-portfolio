Ein Firmeninventar parallel in zwei Systeme migrieren

606 Assets und 129 Lizenzen aus einer Tabelle in zwei Asset-Management-Systeme verschoben, dann nach einer Evaluierungsphase in eines konsolidiert.

Problem

Das komplette IT-Inventar, etwa zwei Millionen Euro wert, lebte in einer Tabelle. Keine Historie, keine Zuordnung zu Benutzern, keine Abschreibung, keine Lizenzübersicht und keine Möglichkeit zu beantworten, wer welches Gerät hat.

Vorgehen

Statt auf ein Produkt zu setzen, migrierte ich parallel in zwei Kandidatensysteme und betrieb beide für eine Evaluierungsphase. Gleiche Quelldaten, gleiche Kategorien, damit der Vergleich fair war.

Lösung

System A erhielt die Daten aufgeteilt in Assets, Zubehör, Komponenten und Lizenzen über 15 Kategorien mit einem benutzerdefinierten Feldsatz für firmenspezifische Attribute. System B erhielt neun Objekttypen einschließlich eines benutzerdefinierten Asset-Typs für Möbel, mit Finanzdaten an jedem Objekt. Nach der Evaluierung wurde ein System gewählt und das andere schreibgeschützt als Referenz behalten.

Ergebnis

Ein vollständiges, abfragbares Inventar mit dokumentiertem Wert, plus eine Entscheidung auf Basis von Evidenz statt einer Anbieter-Demo.

Was ich gelernt habe

  • Zwei Systeme mit echten Daten zu evaluieren kostet mehr Zeit als Vergleichsartikel zu lesen und ist die einzige Methode, die eine vertretbare Entscheidung produziert.
  • Feldnamen in einer API stimmen selten mit den Beschriftungen in der Oberfläche überein. Prüfe die API-Referenz, bevor du Spalten mappst.
  • Ein Tippfehler in einem systemgenerierten internen Namen kann dauerhaft sein. Prüfe das Namensfeld, bevor du etwas speicherst, das zu einem Bezeichner wird.
