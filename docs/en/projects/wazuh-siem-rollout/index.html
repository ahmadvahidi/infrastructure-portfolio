Rolling out a self-hosted SIEM in six phases

Introduced Wazuh as a central SIEM on Docker, planned as six phases so the rollout could not stall halfway.

Problem

The company network had endpoint protection and firewall logging, but no central place where security events from Windows servers, Linux hosts and network devices could be correlated. Nobody could answer the question 'what happened on that machine last Tuesday' without logging into the machine itself.

Approach

Instead of a big-bang installation I wrote a six-phase plan and got it approved before touching anything: phase 0 sizing and host preparation, phase 1 single-node deployment on Docker via Portainer, phase 2 agent rollout on servers, later phases for integrating backup software, Active Directory and the firewall. Each phase had its own success criteria so the project could be paused between phases without leaving a half-configured system.

Solution

Wazuh manager, indexer and dashboard run as a containerized stack managed through Portainer on a dedicated Linux host. Agents were deployed to the server estate first, workstations later. I also built an interactive bilingual dashboard so colleagues who do not read English security jargon could still understand the alert picture.

Result

Phases 0 to 2 are complete and the SIEM is in daily use for alert triage. The phased structure turned out to be the most valuable part: it made the project reviewable by management at every step.

What I learned

  • A rollout plan with explicit stop points survives interruptions. A single long installation script does not.
  • A SIEM without someone reading it is just disk usage. Plan the triage routine at the same time as the deployment.
