Upgrading a production Linux server two versions at once

Ubuntu 22.04 to 24.04 and Java 17 to 25 on a server hosting an integration tool, executed from a written runbook rather than improvised.

Problem

A synchronization tool that keeps two issue tracking systems in sync needed a newer version. That version required a newer Java runtime, which in turn required a newer distribution release. Three upgrades stacked on top of each other, on a server that other teams depended on during working hours.

Approach

I wrote a runbook before starting: current state inventory, snapshot and rollback point, dependency check for every installed package, then the upgrade split into phases with a verification step after each one. I deliberately did not chain the steps so that a failure at any point would leave a system that still booted and still served the old version.

Solution

Distribution upgrade first, then the Java runtime, then the application. Along the way I fixed a systemd unit that had been producing a false monitoring alarm for months because the service reported ready before it actually was.

Result

The upgrade path was executed phase by phase with no unplanned downtime, and one long-standing false alarm disappeared as a side effect.

What I learned

  • When three upgrades depend on each other, write the order down. The dependency chain is not obvious under time pressure.
  • A monitoring alarm that everyone has learned to ignore is a bug, not background noise.
