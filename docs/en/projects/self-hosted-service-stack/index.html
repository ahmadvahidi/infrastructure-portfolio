Building a self-hosted service stack from scratch

Deployed and documented ten open source services behind a reverse proxy, replacing a set of missing or paid tools.

Problem

Several basic functions had no owner: no asset database, no internal wiki, no identity provider, no automation platform, no monitoring. Every gap was being filled by spreadsheets or by nothing at all.

Approach

I picked open source tools that could run on existing hardware, deployed each one as a container, and put them all behind a single reverse proxy with proper certificates. Every service got a written documentation page covering what it is for, how it is deployed, how to back it up and how to restore it.

Solution

The stack covers asset management, monitoring, SIEM, identity and single sign-on, file sharing, automation, documentation and ERP, managed through Portainer with a reverse proxy in front.

Result

Functions that previously lived in spreadsheets now live in systems with access control and history. Because every service was documented at deployment time, none of them is a black box that only one person can operate.

What I learned

  • Documentation written at deployment time takes twenty minutes. Written six months later it takes a day and is wrong.
  • One reverse proxy and one identity provider in front of everything is worth more than any individual service in the stack.
