Importing 735 inventory records without creating duplicates

An automated import that reads a spreadsheet and writes into an asset system, with deduplication that actually works.

Problem

The entire inventory existed as a spreadsheet with 735 rows and had to end up in a real system. Manual entry was out of the question, and a naive import would have created duplicates on every rerun.

Approach

I built the import as an automation workflow rather than a one off script so it could be rerun safely and adapted for the second target system. The deduplication was the hard part.

Solution

Deduplication runs against a paginated fetch of all existing records rather than the search endpoint, because fuzzy search returned near matches that were not the same asset. The import maps spreadsheet columns to categories, custom fields and object types.

Result

735 records imported into two systems in parallel, split across 15 categories with a custom field set for company specific attributes.

What I learned

  • For deduplication, fetch and compare exactly. Do not trust a search endpoint that does fuzzy matching.
  • A batching pattern that works for 50 items can silently break past 100. Test the import at full size, not with a sample.
  • Build imports to be idempotent. You will run them more than once.
