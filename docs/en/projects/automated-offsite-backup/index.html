Solving a full disk with automation instead of a bigger disk

A server ran out of space. The fix combined an automated offsite copy, a data retention policy change and a disk expansion, in that order.

Problem

A log heavy server filled its disk and stopped accepting data. Simply adding space would have delayed the same failure by a few weeks.

Approach

I treated the full disk as three separate problems: the data that already existed and had to be preserved, the policy that let data accumulate without limit, and the capacity that was genuinely too small.

Solution

An automated workflow copies data on a schedule to a dedicated backup server over SSH, the index lifecycle policy was adjusted so old data is aged out automatically, and only then was the disk expanded to a sensible size.

Result

The server recovered, historical data was preserved, and the growth is now bounded by policy instead of by the size of the disk.

What I learned

  • A full disk is usually a retention policy problem wearing a capacity costume.
  • Some SSH implementations require a key generated in the classic PEM format. If key authentication fails for no visible reason, check the key format before debugging permissions.
