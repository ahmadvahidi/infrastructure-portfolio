Mapping a rack and finding a single point of failure

Built an interactive rack plan before a data center visit, and the plan itself exposed a power redundancy gap.

Problem

There was no accurate picture of what sat where in the rack, what it was connected to, and which power feed it used. Every site visit started with reading labels.

Approach

I built an interactive plan as a standalone HTML page: unit positions, devices, and, crucially, power feed per device. Modelling the feeds made the gap visible immediately.

Solution

One management device that everything else depends on was connected to a single feed while the rest of the rack was dual fed. A static transfer switch was specified and purchased to close the gap.

Result

The rack now has a documented plan that can be taken to a site visit, and a known redundancy gap with a purchased fix instead of an unknown one.

What I learned

  • Drawing infrastructure is a diagnostic technique, not documentation busywork. Gaps become visible when you have to place them on a page.
  • Redundancy that is not verified per device is redundancy on paper only.
