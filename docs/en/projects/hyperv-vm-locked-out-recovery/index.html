Recovering a virtual machine nobody could log into

A full system drive blocked login, and after fixing that a broken credential provider blocked it again. Solved from the recovery environment and safe mode.

Problem

A domain joined Windows VM under Hyper-V refused all logins. The system drive was completely full, and there was no way in through the normal desktop to clean it up.

Approach

I expanded the virtual disk from the hypervisor side, then booted into the Windows recovery environment to grow the partition. The disk layout had a trap: the free space sat next to the system partition on one disk while a second virtual disk carried another drive letter, so selecting the wrong volume would have failed or worse. I verified the disk and partition numbers before extending anything.

Solution

Partition extended from the recovery environment, which restored roughly fifty gigabytes of headroom. Login still failed, this time because a multifactor credential provider had broken and was blocking the logon screen. I booted into safe mode with networking, enabled the Windows Installer service inside safe mode through a registry key so that uninstallation was even possible, removed the product, then cleaned the leftover credential provider registry entries, folders and services, and confirmed the machine was excluded from the deployment that would have reinstalled it.

Result

The machine came back without a rebuild and without data loss. Total downtime was a few hours instead of a reinstall.

What I learned

  • Always confirm disk and partition numbers in the recovery environment before extending. The numbering is not the same as in the running system.
  • Windows Installer does not run in safe mode by default. One registry key makes uninstall possible when nothing else works.
  • After removing a credential provider, clean its registry entries too, otherwise the logon screen keeps trying to load something that is gone.
