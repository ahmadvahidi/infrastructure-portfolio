A structured method for an email client that will not start

Seven ordered steps that find the cause in most cases, arranged so the cheapest test comes first.

Problem

A colleague reported that the classic email client would not launch at all, even after a restart. Reinstalling is the common reaction and is almost always the wrong first move.

Approach

I built a sequence ordered by cost and by likelihood, so the fastest and least invasive tests run first and every step either fixes it or eliminates a cause.

Solution

Check for a hung process still holding the application; start in safe mode; disable add-ins one at a time; reset the navigation pane and views via command line switches; create a fresh profile; run a quick repair and then an online repair; finally check whether a recent update coincides with the failure. In practice the safe mode and add-in steps identify the cause most of the time, with document or meeting add-ins being the usual culprits.

Result

A reusable checklist rather than a one time fix, plus a short message template so the user can run the first test themselves before anyone books a remote session.

What I learned

  • Order troubleshooting steps by cost, not by how likely each one feels. The cheap tests eliminate whole branches.
  • Safe mode is the fastest way to separate the application from its extensions. Start there.
  • Let the user run the first step. It saves an appointment in half the cases.
